# Employee Leave Management System

An Employee Leave Management System learning project built to explore backend application development with .NET 10, Oracle 26ai, Visual Studio Code, Git, and GitHub Copilot Agent.

## Purpose

This project is intended to model a practical business application for managing employee leave requests and related administrative workflows. It will be used as a learning workspace for building software incrementally with GitHub Copilot Agent while practicing clear requirements gathering, project organization, source control, database design, and .NET backend development.

The application is not yet implemented. Features, data model, architecture, frontend approach, and testing tools will be decided as the project evolves.

## Intended Users

- Employees who need to request leave and view the status of their requests.
- Managers who need to review leave requests from their team members.
- HR or administrative users who need to maintain leave-related information.
- Developers learning how to build and evolve a professional application using AI-assisted development tools.

## Planned Features

The following features are planned at a high level and may be refined during implementation:

- Submit employee leave requests.
- View submitted leave requests and their current status.
- Review, approve, or reject leave requests.
- Track basic leave types such as vacation, sick leave, or unpaid leave.
- Maintain employee and manager information needed for leave workflows.
- Store leave-related data in an Oracle 26ai database.
- Provide clear documentation as requirements and technical decisions are made.

Additional features will be added only after the core workflow and requirements are clarified.

## Learning Objectives

This project is designed to support hands-on learning in the following areas:

- Using GitHub Copilot Agent to assist with requirements analysis, planning, code generation, and code review.
- Building a .NET 10 backend application in Visual Studio Code.
- Connecting application code to Oracle 26ai.
- Organizing a project so that source code, database assets, documentation, and tests are easy to find.
- Practicing Git-based development workflows.
- Making technical decisions incrementally and documenting them clearly.
- Avoiding premature implementation details until requirements are understood.
